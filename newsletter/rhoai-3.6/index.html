New product

MaaS Portal. A front door for models.

Developers who call models, but never run clusters, now have a place of their own. They see the endpoints they have been granted, create API keys and follow their usage. Administrators govern it all from one view. The portal ships as its own distribution, built from the same code as the RHOAI dashboard.

RHAISTRAT-1545

 

First step

Community plugins. A first step.

Until now, only Red Hat teams could add a page to the dashboard. 3.6 takes the first step towards opening it up: a minimal registration contract where a plugin is declared once, the operator validates it and federates it next to the built-in modules, and it appears in RHOAI under its own path. Each entry is checked on its own, so a bad one never affects the rest of the dashboard. It is an early foundation for experiments, not yet a supported plugin ecosystem; that is the work ahead.

OpenShift 5

Ready for OpenShift 5.

OpenShift 5 changes four defaults at once: networking is closed unless allowed, every component must follow the cluster's TLS profile, clusters can sign users in through an external identity provider, and operators install through OLM v1. Each one was a release gate for 3.6. The dashboard clears all four, so customers can move to OpenShift 5 without waiting on us.

 

Closed by default, open where it should be.

Every dashboard component, from the main dashboard to each module and the MaaS Portal, now ships its own least-privilege network policy: who may call it, and exactly what it may call. Switching it on did what it should. It surfaced undocumented dependencies on pipelines, MLflow and cluster metrics, and we fixed them in nightly builds, before any customer could hit them.

RHOAIENG-93714  · RHAISTRAT-2829

 
 

One TLS profile, everywhere.

The operator and all ten backends now read the cluster's TLS profile and adapt when it changes, instead of hardcoding versions. A TLS scanner runs in CI, and post-quantum key exchange is validated on every endpoint.

RHOAIENG-75339  · RHOAIENG-95823  · RHOAIENG-91147

 
 

Works with any identity provider.

When a cluster signs users in through an external OIDC provider, OpenShift's own OAuth server goes away. The dashboard resolves who you are without it, so sign-in keeps working on day one.

RHOAIENG-93083  · RHAISTRAT-803

Installed the new way.

OpenShift 5 installs operators through OLM v1 instead of the classic model. The dashboard and its operator now recognise both: Subscriptions and CSVs on OpenShift 4, ClusterExtensions on OpenShift 5. Customers can move to the new OpenShift without the dashboard losing track of the platform, its dependencies or the features they unlock. The OLM v1 compliance sign-off is done, and the full end-to-end suite runs on OpenShift 5 before GA.

Quality

Built not to break.

The Dashboard Operator installs and upgrades every module on every cluster. A regression there is not a bug, it is an outage. So in 3.6 every change has to pass three layers of tests before it can merge.

 

Problems caught in a pull request, not in a release.

Fast integration tests check each reconcile path. Conformance tests check the operator against the RHOAI platform contract. Then the change is installed on a real cluster. Issues that used to surface as release blockers, or as customer escalations after an upgrade, now stop at review.
